อัปเดต SPGrid ในโปรเจกต์ที่ใช้งาน

โปรเจกต์ที่ติดตั้งจาก npm (เช่น "@siampiwat/spgrid": "^2.0.10") ไม่อัปเดตเอง package-lock.json ล็อกเวอร์ชันไว้ ต้องสั่งอัปเดตทุกครั้งที่มีเวอร์ชันใหม่ ทำที่โฟลเดอร์ที่มี package.json ของโปรเจกต์นั้น

  1. เช็กเวอร์ชันที่ใช้อยู่และเวอร์ชันล่าสุด 
    npm ls @siampiwat/spgrid
npm view @siampiwat/spgrid version
  2. อ่านประวัติการเปลี่ยนแปลง เปิด ประวัติการเปลี่ยนแปลง แล้วอ่านทุกเวอร์ชันที่อยู่ระหว่างเวอร์ชันของเรากับเวอร์ชันล่าสุด รายการที่มีป้าย BREAKING คือสิ่งที่ต้องแก้โค้ดเดิม
    • patch (2.0.x) แก้บั๊กหรือปรับเล็กน้อย อัปเดตได้เลย
    • minor (2.x.0) เพิ่มฟีเจอร์ โค้ดเดิมยังใช้ได้ ฟีเจอร์ใหม่ปิดไว้เป็นค่าเริ่มต้น
    • major (x.0.0) อาจต้องแก้โค้ด อ่านหัวข้อ BREAKING ก่อนเสมอ
  3. อัปเดตแพ็กเกจ ภายในช่วงเวอร์ชันเดิม (^2.x.x) ใช้ npm update ถ้าข้ามไป major ใหม่ หรือต้องการเวอร์ชันที่ระบุ ใช้ npm install 
    npm update @siampiwat/spgrid              # ภายใน ^2.x.x
npm install @siampiwat/spgrid@latest      # ล่าสุด รวมข้าม major
npm install @siampiwat/spgrid@2.0.10      # เวอร์ชันที่ระบุ
    คำสั่งจะแก้ package-lock.json (และอาจยกค่าต่ำสุดใน package.json) ถ้าต้องการให้ผลคงที่ที่สุด ใส่เวอร์ชันตรง ๆ ไม่มี ^ แล้วอัปเดตเฉพาะตอนตั้งใจ
  4. ตรวจสอบก่อนใช้งานจริง build และรันเทสต์ของโปรเจกต์ แล้วเปิดหน้าที่ใช้ตารางลองดู 
    npm run build
npm test
  5. commit และย้อนกลับถ้ามีปัญหา commit package.json และ package-lock.json พร้อมกัน ถ้าพบปัญหาให้กลับไปเวอร์ชันเดิม 
    npm install @siampiwat/spgrid@2.0.10      # ใส่เวอร์ชันเดิมที่ใช้ได้

ถ้าติดตั้งจากไฟล์ .tgz หรือ git URL (ดู หน้าหลัก) ให้ติดตั้งซ้ำด้วย URL หรือไฟล์ของเวอร์ชันใหม่ เช่น npm install https://github.com/banpotej/siampiwat-spgrid/releases/download/v<เวอร์ชัน>/siampiwat-spgrid-<เวอร์ชัน>.tgz ระหว่างลองไฟล์ที่ยังไม่ publish อย่าลืมสลับกลับเป็นเวอร์ชันจาก npm ก่อน commit

ออกเวอร์ชันใหม่ (สำหรับผู้ดูแล SPGrid)

ทำที่ repo siampiwat-spgrid บน branch main ใน Windows PowerShell ไม่มี CI แล้ว ด่านตรวจคือ npm run check ที่ release.ps1 รันให้

  1. เขียนสิ่งที่เปลี่ยนใน CHANGELOG.md เพิ่มรายการใต้ ## [Unreleased] ในหัวข้อ ### Added, ### Changed หรือ ### Fixed ถ้าเป็นการเปลี่ยนที่ทำให้โค้ดเดิมพัง ใช้ ### Changed (BREAKING) ถ้าไม่มีรายการ release.ps1 จะหยุดก่อนแก้อะไร หน้า ประวัติการเปลี่ยนแปลง อ่านจากไฟล์นี้
  2. เลือกระดับเวอร์ชัน patch แก้บั๊ก, minor เพิ่มฟีเจอร์ที่ไม่ทำให้โค้ดเดิมพัง, major เปลี่ยนที่ทำให้โค้ดเดิมพัง
  3. รัน release.ps1 สคริปต์จะรัน npm run check, commit งานที่ค้างผ่าน gcm.ps1, เพิ่มเลขเวอร์ชัน, อัปเดตเลขในตัวอย่างติดตั้งของ README.md กับ index.html, เปลี่ยน [Unreleased] เป็นเวอร์ชันและวันที่, commit และ tag v<เวอร์ชัน>, npm publish แล้ว push พร้อม tag ต้อง login npm ไว้ (ถ้ายังไม่ได้ สคริปต์เรียก npm login ให้) 
    .\release.ps1                      # patch
.\release.ps1 -Bump minor          # หรือ major
.\release.ps1 -Message "feat: ..." # ระบุข้อความ commit เอง
.\release.ps1 -SkipCheck           # ข้ามการตรวจ (เมื่อเพิ่งผ่านมาแล้ว)
    ถ้า publish ล้มเหลวหลัง tag แล้ว รันซ้ำได้ สคริปต์จะ publish ต่อโดยไม่เพิ่มเวอร์ชันอีก
  4. อัปเดตเว็บไซต์ เว็บ (หน้าหลัก ตัวอย่าง และหน้านี้) ไม่อัปเดตเองตอน publish ต้อง deploy แยก 
    powershell -File deploy-site.ps1 -Pack      # build + zip + deploy ขึ้น Cloudflare
npm run pack:site                           # หรือสร้าง release/spgrid-site.zip แล้วอัปโหลดเอง
  5. แจกไฟล์ .tgz / .zip (ถ้าต้องการ) release.ps1 ไม่ได้สร้าง GitHub Release ให้ ถ้าต้องการให้ลิงก์ .tgz ในหน้าหลักใช้ได้ ให้สร้างไฟล์แล้วแนบกับ Release ของ tag นั้นบน GitHub เอง 
    npm run pack:release      # ได้ siampiwat-spgrid-<เวอร์ชัน>.tgz / .zip ใน release/
  6. ตรวจผล 
    npm view @siampiwat/spgrid version   # ต้องเป็นเวอร์ชันใหม่
    แล้วเปิดหน้าหลักและประวัติการเปลี่ยนแปลง ดูว่าเวอร์ชันล่าสุดขึ้นถูกต้อง จากนั้นแจ้งโปรเจกต์ที่ใช้งานให้ทำตามขั้นตอนด้านบน
