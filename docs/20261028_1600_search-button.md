## การตีความคำขอ

"การค้นหาขอให้เป็น button" ผมตีความว่าให้ค้นเมื่อกดปุ่ม "ค้นหา" แทนการกรองสดขณะพิมพ์ ถ้าหมายถึงอย่างอื่น
(เช่น ให้ไอคอนแว่นขยายเป็นปุ่ม หรือให้กรองสดต่อไปแต่มีปุ่มด้วย) บอกได้

## สิ่งที่ทำ

- ตัวเลือกใหม่ `searchButton?: boolean` (ค่าเริ่มต้นปิด ใช้คู่กับ `searchable`): เพิ่ม `<button type="button" class="dg-search-submit">` ข้างช่องค้นหา
- เมื่อเปิด: พิมพ์ไม่กรอง (ไม่มี debounce, `searchDebounce` ไม่มีผล) กรองเมื่อคลิกปุ่มหรือกด Enter ในช่อง
  Enter ที่ใช้ยืนยันตัวอักษรของ IME (`isComposing`) ไม่นับ และ `preventDefault` กันการ submit ฟอร์มที่ครอบอยู่
- ส่งข้อความว่าง = ล้างตัวกรอง; ปุ่มล้าง (x) ยังล้างทันที; select เลือกคอลัมน์ยังกรองใหม่ทันที; `setFilter()` ทำงานเหมือนเดิม
- `filterChange` ยิงครั้งเดียวต่อการค้นหาที่ทำให้ตัวกรองเปลี่ยน (กดซ้ำด้วยข้อความเดิมไม่ยิง)
- label ใหม่ `labels.searchButton` ("Search" / "ค้นหา") ถูก escape
- สไตล์: ปุ่มสีทึบตามสี accent สูงเท่าช่องค้นหา มี hover/active/focus ring; toolbar ใช้ flex เมื่อมีปุ่มหรือ select
- เปิดใช้ใน `examples/index.html` (หน้าตัวอย่างหลัก); อัปเดต `docs/API.md` (ส่วน Search button, options, labels) และ `CHANGELOG.md`
- ไฟล์ที่แก้: `DataGrid.js` (+1 บรรทัด เหลือ 290/300), `render/toolbar.js`, `render/searchEvents.js`, `render/controls.js`, `render/labels.js`, `styles/toolbar.css`, `types.js`
- test ใหม่ `tests/unit/DataGrid.search-button.test.js` (9 test); `DataGrid.filter.test.js` เพิ่ม `'keydown'` ในรายการ listener ที่ถูกถอดตอน destroy

## เพิ่มภายหลัง: ปุ่ม Clear search (ปุ่มรอง)

- เมื่อเปิด `searchButton` จะมีปุ่มรองแบบ outline `<button class="dg-search-reset">` ต่อจากปุ่มค้นหา ข้อความจาก `labels.clear` ("Clear search" / "ล้างการค้นหา")
- กดแล้วล้างช่อง ล้างตัวกรองทันที และคืน focus ให้ช่อง (ใช้ flow เดียวกับปุ่ม x ในช่อง จึงยิง `filterChange` ตามเดิม) ไม่รีเซ็ตคอลัมน์ที่เลือกใน select
- ปุ่ม x ในช่องยังอยู่ (แสดงเมื่อมีข้อความ); ปุ่มรองแสดงตลอด และไม่ใส่ `disabled` เมื่อช่องว่าง
- test: unit เพิ่ม 2 รายการ (รวม 284), e2e เพิ่ม 1 รายการ (รวม 24) ดู screenshot ด้วยตาแล้ว
- ข้อสังเกต: e2e ครั้งแรกล้มเพราะผมสมมติว่าผลค้นหา "พรีมาออฟฟิศ" น้อยกว่า 10 แถว ซึ่งไม่จริง แก้ที่ test

## เพิ่มภายหลัง: ไอคอนและสีของปุ่ม Search / Clear search

- ปุ่ม Search มีไอคอน `search` และปุ่ม Clear search มีไอคอน `close` หน้าข้อความ (ใช้ไอคอนในตัวเดิม จึงแทน SVG ผ่าน `options.icons` ได้) ไอคอนซ่อนจาก screen reader ชื่อปุ่มไม่เปลี่ยน
- Search: สีทึบตาม `--dg-accent` พร้อมเงาบางๆ hover เข้มขึ้น (`color-mix` กับสีดำ 12%)
- Clear search: tonal สีเทา (`--dg-neutral`) พื้นอ่อน ขอบโปร่ง hover เข้มขึ้น ให้เป็นปุ่มรองแบบเดียวกับปุ่ม action
- กดแล้วขยับลง 1px; ปิด transition ตาม `prefers-reduced-motion`
- ไม่เพิ่ม API ใหม่; ดู screenshot สว่าง/มืดด้วยตาแล้ว; unit test เพิ่ม 1 รายการ
- ข้อควรระวัง: ใช้ `color-mix()` (Chrome/Edge 111+, Safari 16.2+, Firefox 113+) และ `--dg-neutral` ที่ใช้ `light-dark()` (Chrome/Edge 123+, Safari 17.5+, Firefox 120+) ถ้าเบราว์เซอร์เก่ากว่านั้น สีปุ่ม Clear อาจไม่ขึ้น

## เพิ่มภายหลัง: Input Group (รวมส่วนค้นหาเป็นแถบเดียว)

- ตอบคำถาม "ทำเป็น Input Group ได้ไหม": ได้ และทำแล้ว ส่วนค้นหาห่อด้วย `<div class="dg-input-group">` เรียง select คอลัมน์ → ช่องค้นหา → ปุ่ม Search → ปุ่ม Clear search
  เชื่อมขอบติดกัน (ทับเส้นขอบ 1px ไม่ให้เส้นซ้อน) โค้งเฉพาะมุมนอกสุด ส่วนที่ไม่ได้เปิดไม่ถูกเรนเดอร์
- hover / focus ของส่วนใดส่วนหนึ่งยกขึ้นเหนือเพื่อนบ้าน ให้เส้นขอบและ focus ring แสดงครบ
- container กว้างไม่เกิน 520px (container query) แยกเป็นหลายแถว: ช่องค้นหาเต็มแถวบน ส่วนที่เหลือเรียงด้านล่าง มุมโค้งครบทุกส่วนอีกครั้ง
- **ผลข้างเคียง:** select คอลัมน์ย้ายจากหลังปุ่มมาอยู่หน้าสุด (ลำดับ DOM/Tab เปลี่ยนตามที่เห็น); ลบกฎ `.dg-toolbar:has(...)` เดิมที่ใช้ flex แทน
- ไม่เปลี่ยน public API; unit test เพิ่ม 2 รายการ (โครงสร้างกลุ่ม); ดู screenshot สว่าง/มืด/แคบ (420px) ด้วยตาแล้ว
- ข้อสังเกต: ใช้ container query (Chrome/Edge 105+, Safari 16+, Firefox 110+); ยังไม่ได้ดู RTL
