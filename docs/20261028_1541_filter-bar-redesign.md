## การตีความคำขอ

"filter control" ผมตีความเป็นแถบค้นหา/กรองที่มีอยู่ (select คอลัมน์ + ช่องค้นหา + ปุ่ม Search + ปุ่ม Clear search) ซึ่งเป็น Input Group อยู่แล้ว
ถ้าหมายถึงตัวกรองรายคอลัมน์ (`columnFilters` ที่ยังไม่มี UI) บอกได้ เป็นฟีเจอร์ใหม่แยกต่างหาก

## สิ่งที่ทำ

- เขียน `src/styles/toolbar.css` ใหม่ทั้งไฟล์ให้เป็นระบบเดียว (ส่วนที่ใช้ร่วมกันรวมไว้ที่เดียว)
- ทุกส่วนสูงขึ้นเป็น `2.75em` ขอบเสมอกัน; กลุ่มทั้งแถบมีเงาบางๆ และมีเงาเรืองรอบนอก (`0 0 0 3px` สี focus 25%) เมื่อส่วนใดส่วนหนึ่งมี focus
- select คอลัมน์เป็น addon สีอ่อน (สีเดียวกับหัวตาราง) ตัวอักษรหนาปานกลาง มีลูกศรของตัวเองวาดด้วย gradient ตามสีตัวอักษร (ใช้ได้ทั้งสว่าง/มืด) และสลับตำแหน่งใน RTL (`:dir(rtl)`)
- ช่องค้นหามี placeholder (ข้อความจาก `labels.search` ต่อด้วย "…") ขอบและไอคอนเปลี่ยนเป็นสี focus ตอนพิมพ์; ปุ่ม x ในช่องเป็นวงกลม
- ปุ่ม Search สีทึบ (ปุ่มหลัก) ปุ่ม Clear search tonal สีเทา (ปุ่มรอง) ไม่ใช้เงาที่ปุ่มเพื่อไม่ให้ซ้อนกับเงาของกลุ่ม
- focus ring ของแต่ละส่วนวาดด้านใน (`outline-offset: -3px`) ไม่ถูกส่วนข้างเคียงบัง
- จอแคบ (container ≤ 520px) ยังแยกเป็นหลายแถวเหมือนเดิม และปิดเงาของกลุ่ม
- ปิด transition ตาม `prefers-reduced-motion`
- markup: เพิ่ม `placeholder` ที่ช่องค้นหาเท่านั้น (ชื่อสำหรับ screen reader ยังมาจาก `aria-label`)
- อัปเดต `docs/API.md` (ย่อหน้าดีไซน์ในส่วน Input Group) และ `CHANGELOG.md`

## ข้อตัดสินใจ

- ไม่เปลี่ยน API หรือโครงสร้างองค์ประกอบ (ยังเป็น `.dg-input-group` เดิม) เพื่อให้ test และเอกสารเดิมใช้ต่อได้
- เสียงเรืองรอบนอกใช้สี focus เดียวกับ ring เพื่อไม่เพิ่มตัวแปรสีใหม่

## ข้อสังเกต

- `placeholder` ซ้ำกับ `aria-label` ตั้งใจ (placeholder เป็นแค่คำใบ้ที่เห็น ไม่ใช่ชื่อหลัก)
- ใช้ `color-mix()` และ `:dir()` (Chrome/Edge 120+, Safari 16.4+, Firefox 49+) เบราว์เซอร์เก่ากว่านั้นเงาเรืองหรือสี hover อาจไม่ขึ้น ส่วน RTL ยังไม่ได้ลองจริง
- test ตรวจโครงสร้าง ไม่ตรวจหน้าตา ยืนยันด้วย screenshot ด้วยตาเท่านั้น
- ยังไม่ได้ดู forced-colors (เงาเรืองจะไม่แสดง แต่ outline ภายในยังแสดง)

## เพิ่มภายหลัง: ปุ่ม Search / Clear search ไม่มีข้อความ (ไอคอนล้วน)

วันที่: 2026-10-28 15:44 | ผลตรวจ: `npm run check` ผ่าน (287 unit test), e2e ผ่าน 24 รายการ

- ปุ่มทั้งสองเหลือเฉพาะไอคอน (`search`, `close`) ชื่อสำหรับ screen reader ใส่ผ่าน `aria-label` และ tooltip ผ่าน `title` จาก `labels.searchButton` / `labels.clear` (escape แล้ว) ไม่เสียการเข้าถึง
- CSS: ปุ่มกว้างขั้นต่ำ `2.75em` ไอคอนใหญ่ขึ้นเป็น `1.4em` ไม่มี gap/น้ำหนักตัวอักษรแล้ว
- test: แก้ unit test เดิมที่ตรวจ `textContent` ให้ตรวจ `aria-label`/`title` และตรวจว่าในปุ่มมีแต่ไอคอน 1 อัน; e2e ไม่ต้องแก้ (หาปุ่มด้วยชื่อ)
- อัปเดต `docs/API.md` และ `CHANGELOG.md`
- ข้อสังเกต: `labels.searchButton` / `labels.clear` ยังใช้ได้ แต่ตอนนี้ปรากฏเป็นชื่อ/tooltip ไม่ใช่ข้อความบนปุ่ม

## เพิ่มภายหลัง: filter control ชิดขวา

- `.dg-toolbar` เป็น flex แบบ `justify-content: flex-end` แถบกรองจึงชิดขอบท้าย (ขวา) ของตาราง ใช้ค่า logical จึงสลับเป็นซ้ายอัตโนมัติใน RTL
- จอแคบ (container ≤ 520px) กลุ่มเต็มความกว้างอยู่แล้ว จึงเหมือนเดิม; ดู screenshot ทั้งจอกว้างและแคบแล้ว
- ข้อสังเกต: ช่องค้นหาเดี่ยว (ไม่เปิด select/ปุ่ม) ก็ชิดขวาเช่นกัน
