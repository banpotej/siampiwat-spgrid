## การตีความคำขอ

"footer" ผมตีความเป็นแถบใต้ตาราง (ข้อความสรุป "แสดง 1–10 จาก 60 รายการ" + select จำนวนแถวต่อหน้า + pager) ซึ่งไลบรารีไม่มี element ชื่อ footer แยก

## สิ่งที่ทำ (ไฟล์เดียว: `src/styles/pager.css`)

- pager เป็น pill แบบ segmented: ปุ่มไม่มีขอบบนพื้นสีเทาอ่อน (tint ของ `--dg-neutral`) มุมโค้งตามธีม; หน้าปัจจุบันเป็นชิปสี accent ทึบ ตัวหนา เงาบางๆ; hover เป็นพื้นอ่อนเข้มขึ้น; ปุ่มที่ใช้ไม่ได้จางลง (ค่า 0.5 ตามที่เอกสารระบุ)
- select จำนวนแถวต่อหน้าใช้สไตล์เดียวกับ select ในแถบกรอง: พื้นอ่อน ไม่มีขอบ ลูกศรของตัวเอง (สีตามตัวอักษร) น้ำหนักปานกลาง รองรับ RTL ผ่าน `:dir(rtl)`
- ช่องไฟกว้างขึ้นระหว่างส่วนต่างๆ ของ footer ตัวเลขใช้ `tabular-nums` เพื่อไม่ให้กระโดดเวลาเปลี่ยนหน้า
- ปิด transition ตาม `prefers-reduced-motion`
- ลบกฎ `.dg-search-field { max-width: none }` ใน container query ของ footer ซึ่งไม่จำเป็นแล้วหลังทำ input group
- อัปเดต `docs/API.md` และ `CHANGELOG.md`

## ข้อตัดสินใจ

- ไม่เปลี่ยน markup ของ pager (`render/pager.js`) และ API เหมือนเดิม; test เดิมใช้ต่อได้ทั้งหมด
- **เปลี่ยนค่าเริ่มต้น:** `--dg-pager-border` และ `--dg-pager-bg` เดิมเป็นเส้นขอบ/พื้นของปุ่ม ตอนนี้ค่าเริ่มต้นเป็นโปร่งใส ผู้ที่ตั้งสองตัวแปรนี้เองจะยังได้ผลเหมือนเดิม
- ใช้ตัวแปรสีเดิม (`--dg-neutral`, `--dg-accent` ฯลฯ) ไม่เพิ่มตัวแปรใหม่

## ข้อสังเกต

- ใช้ `color-mix()` และ `:dir()` เบราว์เซอร์เก่ากว่า Chrome/Edge 111/120, Safari 16.4 พื้น tint อาจไม่ขึ้น ส่วน RTL ยังไม่ได้ลองจริง
- ยังไม่ได้ดูโหมด forced-colors (ขอบปุ่มยังเป็น `1px solid transparent` จึงถูกระบบเติมสีให้) และอุปกรณ์ touch (กฎ 44px เดิมยังอยู่)
- ตอนรัน e2e ด้วย worker เริ่มต้น (6) บนเครื่องนี้เบราว์เซอร์ปิดตัวเองเป็นระยะ (`browserType.launch`) ไม่เกี่ยวกับโค้ด ใช้ `--workers=2` ผ่านสม่ำเสมอ
